# qLDPC 魔态工厂：接受率差距来自哪里？

**结果：代数结构可以独立核验；完整噪声下的制备译码显著提高接受率，但作者的绝对接受率、完整条件逻辑错误率和资源优势尚未复现。** 本报告截至 2026-10-13，针对 Menon 等人的 [arXiv:2610.10731v1](https://arxiv.org/abs/2610.10731v1)。这是一个有实质数值结果的部分复现。

## 1. 论文解决什么问题

qLDPC 码可以在较少物理比特上编码多个逻辑比特，但通用量子计算还需要非 Clifford 资源。本文把两种码连接起来：先在 tricycle 码中利用横向门生成逻辑魔态，再通过 escape 操作转移到距离更大的 quadcycle 码，并用后选择拒绝可检测的故障。

理解工厂性能必须同时看三件事：一次尝试被接受的概率、接受后的逻辑错误概率，以及每个有效输出的资源成本。单独检查码矩阵，或者只得到一个漂亮的逻辑错误曲线，都不能证明整套工厂的资源优势。

本文提出中性原子实现方案；这里核验的是理论、线路与数值结果。实际原子操控实验不属于本报告已执行的工作，也没有被用来解释尚未完成的经典计算。

## 2. 从量子码到可计算对象

我们把有限群上的多项式展开为二元循环置换矩阵，在 GF(2) 上检查

$$
H_XH_Z^T=0,\qquad M_XH_X=M_ZH_Z=0,
\qquad k=n-\operatorname{rank}H_X-\operatorname{rank}H_Z.
$$

第一式保证 CSS 稳定子对易；第二组给出冗余测量之间的元校验关系；第三式给出逻辑比特数。五组 Table II 参数全部通过这些精确检查，tricycle 编码 3 个逻辑比特，quadcycle 编码 6 个。

| tricycle 物理比特数 | tricycle 距离结论 | quadcycle 物理比特数 | quadcycle 距离结论 |
|---:|---:|---:|---|
| 27 | (6,3) | 54 | 精确距离 6 |
| 36 | (8,4) | 72 | 精确距离 8 |
| 81 | $d_X\le15,\ d_Z=5$ | 162 | 显式逻辑算符给出 $d\le14$ |
| 114 | $d_X\le19,\ d_Z=6$ | 228 | 显式逻辑算符给出 $d\le17$ |
| 210 | $d_X\le28,\ d_Z=7$ | 420 | 显式逻辑算符给出 $d\le21$ |

大码的上界不是最小距离证明。420 比特码的权重 21 见证改进了原文启发式估计 25，不能据此声称推翻了一个精确距离定理。详见[推导与检查口径](../docs/DERIVATION.md)、[代数结果](../outputs/data/algebra.json)和[距离见证](../outputs/data/extra-distances.json)。

## 3. 噪声、译码和后选择怎样进入计算

当前接受率计算保留完整 SD6 基本通道：单比特门与 idle 的去极化概率为 $p$，双比特门采用总概率为 $p$ 的双比特去极化，制备和测量有概率 $p$ 的翻转。CCZ 的单 pair 边缘通道采用均匀非平凡 Pauli 约定，概率为 $16p_{\rm CCZ}/21$。这是声明的 Clifford 相位诊断模型，不能直接等同于完整魔态 infidelity。

每一次工厂尝试都进入接受率分母；失败的制备没有预先删除。最终 quad 读出不用于后选择。实际可访问的 quad 元校验记录记为 $S$；制备产生的未知 frame 记为 $F$；接受检测器为 $D$。后选择事件为

$$
A=\{D\oplus\widehat F(S)=0\},\quad
\alpha=P(A),\quad p_L=P(L\ne0\mid A).
$$

这里的分母和条件事件必须一致。MAP 对同一 frame 的所有故障解释求和，再选后验概率最大的 frame；MLE 选择最可能的一条独立 DEM 故障解释。两者有区别。构造概率模型时使用的理想标签没有提供给运行中的 decoder。

具体参数、门序、噪声时点和算法实现见[数值方法](../docs/NUMERICAL_METHODS.md)。生成程序只读取模型与配置，原图读数仅用于后续比较。

## 4. 接受率：改善有多大，差距还剩多少

固定 $p=0.001$、$p_{\rm CCZ}=0.002$，采用声明的 `fresh_aligned` 时序及默认固定门序。下表都是每次尝试生成单 pair 的接受概率。

| 规则 | 54 码 | 72 码 |
|---|---:|---:|
| 原图读数，约 | 74.4453% | 65.9287% |
| 直接使用 noisy frame | 66.0619% | 55.0104% |
| 电路级 frame MAP | 70.6444% | 62.9821% |
| 电路故障 MLE | 70.6362% | 62.9706% |
| 假想精确知道 quad 制备 frame | 73.5470% | 66.3845% |

图中曲线来自[实际生成数据](../outputs/data/preparation/results.json)，不是作者曲线的描摹。下面的比较图加入原图读数；这些读数有读图误差，不是作者原始数组。

![接受率比较](../docs/comparisons/preparation-acceptance.png)

比较对象为原文 Fig. 5(b)，来源为上述 arXiv v1。图中的参考内容仅用于必要的复现核验，不属于本仓库开放内容许可；数值接近不证明与作者原数组逐点等同。

MAP 后剩余差距约为 **3.8009 和 2.9466 个百分点**。八个源读点的 RMSE 为 **3.4349 个百分点**，最大偏差 **4.0216 个百分点**。本轮完成了 44 个配置、96 个 tricycle 顺序对照和 400 万条实际 gate-level 抽样；这些是计算规模，不是论文完成率。

一个有用的定位结果是：在固定剩余线路和信息集合下，54 码即使精确获知 quad 制备 frame，接受率仍比原图低约 0.8983 个百分点。因此，只改这部分 decoder 不能完全解释差距。联合其他可访问记录、不同合法后选择条件以及更广门序仍需我们继续排查；不能提前归因于作者写错或信息缺失。

## 5. 这些结果有多可靠

接受率来自有限二元联合分布的精确求和，采用 float64 实现，因此没有 Monte Carlo 抽样误差，但也不是区间算术证明。分布归一化、字符变换、噪声因子分解、实际门级抽样和另一套小模型枚举提供了交叉检查。MAP 的信息上界只适用于指定记录，不能推广到所有联合 decoder。

每种码另扫描了 160 个 tricycle schedules；其中各 32 个达到该候选族最高的已证明 phase-probe distance，分别为 3 和 4。这些候选的 MAP 接受率和理想 frame 上界相同，未用低距离门序贴合原图。有限候选族仍不等于全局门序最优。

原图、复现图和差分图可在[历史像素比较](../docs/COMPARISONS.md)查看。该版本早于本轮制备译码修正，不能拿旧像素误差评价最新 MAP 曲线。字体、坐标和布局误差与数值差距分别解释。

## 6. 已完成什么，还有什么没有完成

本报告交付码结构、距离证据、声明线路下的接受率、有限门序和故障检查。**完整条件逻辑错误率、较大码稀有错误率、$10^{-9}$ 输出指标及 10–40 倍资源优势仍未闭合。** 已认证的低阶故障子集中没有发现错误，不等于完整逻辑错误率为零。

原文附带动画的码坐标与 CCZ 门表还存在组合一致性问题，必须限定在该 ancillary 实现审计的范围内；它不自动否定抽象工厂构造。本公开包聚焦独立计算，没有重新分发作者动画，也不把这项审计并入接受率结论。

可运行的剩余工作、能够消除歧义的作者信息以及实验能力边界分别列在[差异与待办](../docs/BOUNDARIES.md)。报告不把“尚未做完”算作外部受阻。两篇研究均未向作者发送邮件。

## 7. 怎样复算

从仓库根目录创建 Python 环境，安装本案例的 `code/requirements.txt`，然后执行：

```bash
python cases/2610.10731/code/scripts/run_reproduction.py --mode quick
python cases/2610.10731/code/scripts/run_reproduction.py --mode preparation
```

`quick` 重新计算五组码的代数恒等式及一个原参数接受率控制；`preparation` 重跑完整 44 配置接受率实验，历史墙时约 24.5 分钟，随硬件变化。计算写入新的临时目录，保留仓库中的冻结数据。快速检查不是全文复现。

若只想核对已发布结果或重画图，可用 `--mode verify` 或 `--mode render`。环境、图表输入和具体执行边界见[复算说明](../docs/NUMERICAL_METHODS.md)。
